# CourtLens Broadcast｜赛前工程进展

2026-10-01。本轮以视频理解可靠性为第一优先级。正式输入是两段训练进攻合计约48秒、抽签对应的一段考试视频；输出仍是把解释叠加回原画面的影片和交互观看页。规则依据是用户提供的培训纪要，精确模型、区域和 Agent 服务名等待 Portal 原文。

## 本轮落地

| 优先级 | 模块 | 可使用的结果 | 验收与边界 |
|---|---|---|---|
| P0 | AWS 视频候选接纳 | 一次最多12个动作候选，独立校验人名、时间、源帧；坏候选单独进入复核，保留可用邻项 | 本地真实MP4和PNG走模拟Converse接口及AgentCore交接；不等于真实模型识别准确率 |
| P0 | 视觉模型能力与探测 | 显式声明text/image/video及工具支持，逐帧和视频探测分别保存；模型、区域、profile、声明改变后旧探测失效 | 默认只开放文本能力；声明是配置，实际接通必须真实探测，成功也不证明篮球事实正确 |
| P0 | 指定源帧探测 | 选择视频后半段源帧时发送该张真实图片，云端为它生成局部范围；篡改图片在调用前拒绝 | 本地媒体与模拟接口实测；未调用AWS |
| P1 | 切镜候选和重点取证 | 本地CLI逐源帧扫描切镜，按最多两个4秒窗、20fps准备原始证据；每个镜头片段重置身份作用域 | 48秒本机样片1200帧扫描3.57秒，两个窗161张PNG总26.54秒；只是一例耗时，不是精度/实时承诺 |
| P1 | 正式交付证据交接 | 检查10项配置和证据合同，包括仓库、Portal、账号、区域、CDK、CloudFront、Agent及模型授权；输出后续任务 | 附件哈希和版本一致性检查，绝不把离线报告当成云资格认证 |

AWS候选处理现在允许最多32张已见源帧，并与云端交接使用同一上限；原始可见响应在本地校验前保存，过滤推理内容和非白名单usage字段。格式修复失败仍留本地审计。Agent运行时的失败响应没有新增持久化，不能把本地审计能力说成云端失败留证已完成。成功云交接保留原始可见JSON及哈希，再独立复核像素。

动作候选可以多于3条，画面分析仍限制重点节点，避免为了连续口播把12张指标卡同时放上屏幕。通过名单与时间校验的候选仍全部是未审核状态，合法ID不证明该球员出现在画面。没有官方 xFG/Gravity/LVG 的事件继续不显示数值。

## 使用方式

现有完整制作台、CSV/JSON官方数据预览导入、RF-DETR检测、短窗SAM2实验、知识检索、口播编辑和三语影片继续复用。新增取证先作为独立模块工作，不增加制作台配置步骤，也未挂为自动工作流。

准备重点取证：先用现有视觉就绪报告的 `reinspectionWindows`，或保存最多两个start/end窗口的JSON数组，然后执行：

```sh
python3 tools/prepare_broadcast_sampling.py \
  --video /absolute/path/input.mp4 \
  --windows /absolute/path/windows.json \
  --output workspace/my-sampling-run --extract
```

输出包含 `scan.json`、`sampling-plan.json` 和真实PNG；候选一律未审。原始PNG保留画面细节，两窗本次占约170.7MB；送模型前需要另行遵守其输入预算，不能把全部帧一次上传。闪光可能误报，同色切镜可能漏报，扫描零候选也不证明全片连续。VFR缺帧保留实际间隔，不合成假证据。

交付检查使用 [说明](Broadcast-赛前部署证据交接.md) 和仓库中的 `infra/contest-delivery.example.json`。当前全部远端事项留待验收，报告不得覆盖已有结果。

## 接下来按顺序收敛

1. **在新增取证证据上复核现有检测和事件候选。** 用陌生片和独立逐帧真值测动作、身份、事件锚点，输出错误清单；未经该验收不承诺全自动实名。
2. **完成云模型分工的实接。** 当前云端仍是一个精确MODEL_ID配置。若Portal提供纯文本Qwen和独立视觉模型，需要拆成两个授权配置；不能只换名称就认定已完成视觉理解。先对自有测试片验证，再在获准范围处理赛方素材。
3. **取得官方字典和样例后适配数据。** 现有导入先预览，再确认比赛、球员、事件、单位和可用时刻。严禁将未知指标填成演示值。
4. **三语原声音色做同稿听评。** 已有普通话、英语、粤语真实TTS影片；接下来比较可懂度、篮球人名、停顿和情绪，不克隆名人声音。语音不是替代视频理解的优先项。
5. **赛方账号后完整云演练。** 指定账号和区域、CDK部署、实际Agent调用、CloudFront影片播放、private仓库及Portal绑定逐项留证。20:00截止前冻结版本和提交地址，不以Pages链接代替正式URL。

Kiro可接续普通代码仓库、CDK配置和JSON任务清单，目前没有确认它是比赛强制工具。上述账号相关事项尚未完成；本轮是赛前软件版本，尚不是正式可交稿验收。

独立审核补充修复：多视频轨输入在媒体检查阶段明确拒绝；抽帧、切镜和模型派生片显式选择第一视频轨。真实双轨反例验证不会错配PTS和像素。三语成片的一条视频、三条音频仍支持。
