# CourtLens Broadcast：设计裁决与验收底稿

日期：2026-09-30。本记录冻结本轮设计决策，开发结果需另附实测，不能把目标写成已完成。

## 采用的方案

两份 Astra 审核均支持方案 C：视频语义提议 → 定向取证 → 官方数据绑定 → 最多三段故事 → 人审 → 原视频叠加成片。GPT-6 Sol High 承担后端、前端和 AWS 工程实现。新入口 `/broadcast/`，保留旧 `/arena/` 和已验证的渲染内核。

不把球队管理、赛季看板或科学训练系统加入本轮主路径。主用户是制作解说片的分析员，最终用户是观看成片的球迷。复杂度来自可靠的视频工作流，而非页面数量。

## 对用户技术建议的裁决

| 建议 | 决定 | 依据与边界 |
|---|---|---|
| 复用 RF-DETR / SAM2 | 采纳为可选视觉插件 | 必须记录权重版本、许可和真实执行结果；不把导入结果称为本系统推理；不在能力查询时下载模型。 |
| 全片稠密追踪作为必需前置 | 调整 | 先选关键时窗取证，避免初始化与推理耗时吞掉现场窗口。完整追踪是增强能力。 |
| 球场投影算距离和引力 | 部分采纳 | 有效镜头校准能支持地面距离；不能由像素距离推导官方 GRAV，也不能跨切镜沿用同一标定。 |
| Bedrock 视频模型负责理解 | 采纳 | 模态、区域、模型 ID 按实际授权配置；模型只产出待复核提议；图像抽帧模式明确标识。 |
| nba_api / pbpstats 补背景 | 采纳但非核心依赖 | 不阻塞 48 秒任务，不替换官方三项指标，不混用赛季概率与单次出手概率。 |
| 低 xFG 等于精彩 | 不采纳自动等价关系 | 低概率可能来自差的选择；精彩与决策价值需要上下文，解释必须保留不确定性。 |
| 每时刻 1–2 项数据 | 采纳并收紧默认值 | 默认一个主要指标加一个简短辅助标签，其余放证据抽屉。 |

## 不可改变的事实边界

- 培训描述是两段训练素材合计约 48 秒；不能转述成每段 48 秒。
- 官方字段粒度、单位、事件键、视频时钟映射尚待 Portal 数据验证。
- xFG、GRAV、LVG 的官方口径不能由第三方指标替代；赛季记录不写入瞬时指标槽位。
- CloudFront、CDK、指定 AWS Agent 服务与私有仓库是提交要求；本地通过不等于比赛资格通过。
- 地区、模型与指定 Agent 服务待核验，不将候选 AgentCore 写成主办方已经确认。
- 软件不能代替现场问答 4 分与投篮挑战 6 分；不承诺拿满机器评分或获奖。

## 验收任务

1. 上传可解码视频，服务端保存真实 SHA-256、时长及时间基准；刷新和服务重启后能恢复。
2. 选择实际视频秒数获取帧，保存实际解码时间与帧 hash；不只画虚拟进度。
3. 人工观察能录入、接受、拒绝；模型未配置时不冒充自动完成。
4. 自动提议绑定输入版本；编辑后的旧任务不能覆盖新内容。
5. 不同游戏、球员、事件、scope 或时间的指标不能进入事件解说；缺数值不会显示成零。
6. 至多三段故事；修改内容撤销审核；审核必须绑定当前内容 hash。
7. 生成真实、可播放、有图层和字幕的 MP4，提供 VTT、成片 hash 与不可变观看入口。
8. 成片取消、失败、语音超窗及不支持的时间基准都明确失败；不发布部分输出。
9. 桌面和 390px 手机可操作，无横向溢出、无限加载或虚假可点击按钮。
10. CloudFormation 本地合成及模板断言通过；没有账号时不运行部署，也不宣称云端验收。

保留原版冻结副本与验证记录。新候选冻结后跑独立验证和相反顺序的两份 A/B 审核；以定位证据决定是否替换，不使用自评总分掩盖失败。官方视频、真实模型与云端未提供的部分独立列为外部验收缺口。

## 开发审核补充裁决

2026-09-30：把事实可用时刻和几何有效窗分开。原架构要求全部观察窗结束后才能开始解说，对明确事件过严，也可能诱使实现把已经过期的箭头画到后续帧。具有明确锚点的出手、接球、传球可在锚点及已取得的帧证据之后解说；描述整个时间窗的结论仍须等窗口结束。坐标始终只能在同一镜头的人工确认有效窗与解说窗的交集内显示。人审不会让过期几何重新有效。

最新约束：用户给定八小时开发窗口；AWS 账号尚未分配。Kiro 是否强制、MiniMax 或 StepFun 是否为指定语音模型均未确认。本轮采用可移交的普通工程入口和可替换的语音适配合同，不能将这些候选写成已获准服务。

## 2026-09-30：以新产品为主，不强求历史兼容

用户明确授权重新设计界面、功能与架构，可删除无关功能，不必延续 CourtLens Arena；能融合的部分择优复用。本版保留已验证的指标口径验证与媒体基础能力，新增独立 Broadcast 合同、服务、制作工作流和成片播放器。旧版只作历史参照，不再出现在新版主导航中，根入口进入 Broadcast。

视觉选择：比赛视频占据主舞台，深海军蓝底配蓝与篮球橙。界面围绕当前制作任务组织，不堆赛季统计，不用装饰性的实时数值或虚假模型状态营造科技感。视觉冲击来自清楚的运动画面、短时定点标注、克制的关键指标和同步解说。

### 人工几何与观察时间的边界调整

动作观察的发生窗口与人工箭头的显示窗口是不同概念。动作已发生后，可以在解说章节起点重新抽取真实目标帧，由人确认坐标，建立新的短时几何证据。人工几何必须在同一镜头段、源视频范围内，并绑定目标帧；最长持有三秒，默认一秒；实际出片只显示章节与几何窗口的交集。不能把上一帧的模型或 CV 坐标自动延长，不能将人工箭头称为自动跟踪。镜头段仍由人工确认，未宣称镜头切换已自动验证。

### 采用与不采用的参考建议

- 采用：视频理解与定向关键帧结合；成熟视觉推理通过提供者接入；官方指标和背景统计分层；一段视频聚焦少数解释节点；真实 MP4、字幕、语音和可交互页面。
- 调整：RF-DETR/SAM2 不作为无条件硬依赖，模型权重、GPU、许可证和实测准确率未确认前不能宣称已接通自动跟踪。
- 调整：语音接口保留供应商选择，MiniMax / StepFun 均待最终选型与真实凭据。macOS 中文语音仅验证本地成片链路，不代表正式比赛配音质量。
- 不采用：附件中的未核验赛季数值、负 Gravity 必然被放空、低 xFG 必然更精彩、两种概率“难一倍”等推断。
- 不采用：把托管服务数量或三个硬性要求视为保证拿满分。架构服务各有职责，实际评分以官方最终细则为准。
