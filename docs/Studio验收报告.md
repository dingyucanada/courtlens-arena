# CourtLens Studio v3 验收报告

日期：2026-09-22。范围：Studio 浏览器应用、静态构建与本机入口兼容；不将软件流程测试当作真实 NBA 预测评测。

## 实际完成的端到端流程

- 从网页创建合成演练项目，编辑复盘笔记，逐条确认 3 个回合，修订从 r1 增至 r7。
- 调整第一段入出点为 9.25–11.5 秒，未保存时点击前往交付被阻止，保存后时间范围生效。
- 批准项目 r9，经页面录制全部 3 个片段，总选段时长 26.25 秒；实际下载 5,077,264 字节 WebM。
- FFprobe 确认下载文件是 VP8、1280×720、单路视频、无音频；FFmpeg 成功解码并抽帧，画面有片段编号、球员、原视频时刻和结果标签。
- 新建另一项目，通过原生文件选择器导入 857,398 字节的合成 MP4；保存为 r2，视频时长 36 秒；没有将内置 URL 当成用户导入成功。
- 实际选择 CSV 文件导入 2 条回合并保存 r3。刷新页面后仍存在，视频和项目恢复。
- 其中一条未知结果、一条三分命中：页面显示已知结果出手 1、命中 1、FG%=100%、eFG%=150%、未知=1、投篮得分=3、xFG 覆盖 1/2、输入期望得分=1.20，口径正确。
- 390×844 手机布局实际检查：页面宽度和视口均为 390，没有整体横向溢出；导航改为底部入口。测试后恢复默认视口。
- 所检查浏览器流程没有记录控制台错误。

另用独立测试页实际执行 15 项 IndexedDB 集成检查，全部通过：原子保存、双连接并发冲突、历史不可变、复核失效、实际媒体存在与尺寸检查、媒体 ID 不可覆盖、恢复、归档与重新打开等。

独立测试页还实际录制 3 秒视频，首次得到 2,190,679 字节 VP8 WebM；最终构建复测得到 617,150 字节 VP8 WebM，两次均在浏览器重新解码为 1280×720。码率和文件大小会随浏览器录制调度变化。MediaRecorder 生成的容器可能没有有限 duration 元数据，因此不把它当作精确剪辑格式。

## 独立审查与修复

由与作者上下文分开的代理复核，不是外部安全审计或真人评委。实际发现并修复：

1. 导入备份的片段 ID 进入未转义字段名，可能注入 HTML：统一转义属性名并加入攻击样本回归。
2. 按钮导航和浏览器历史可能丢失未保存表单：统一保存保护、忙碌锁和历史回退保护。
3. 视频导入及项目选择异步返回可能错绑项目：在异步工作前冻结目标，统一导航序列及旧页面检查。
4. 合法小数秒与表单步长不兼容：允许任意有效精度。
5. 缺失项目路由和重绘表单未释放/继承锁：增加相应恢复检查。

首轮独立复跑 Studio 60 项通过。后续成对复核发现原 CourtLens JSON 的高级字段被简化且无提示，增加了原始回合证据和指标语义留档、只读查看、备份保留及明确范围提示。增加原始证据往返、未知字段、恶意 HTML、容量放大预检和深层备份恢复边界回归后，Studio 共 68 项通过；其中一项存储实测还覆盖证据随历史恢复保留。另实际下载新项目备份并核对：首回合 Gravity=1.8、Leverage=0.82、25 条轨迹、2 条标注及指标语义全部保留。未因此声称已在 Studio 实现高级战术叠加。

## 尚未验证

不同浏览器和手机实机的媒体兼容、长时间大素材压力、正式 NBA 数据的真实准确率、多人协作、云模型真实调用、外部渗透测试与主办方最终资格规则。本版本为可用的单用户工作室，不宣称已经具备多租户 SaaS 服务能力。

## 发布收尾修复

成对评审选定版本后，针对另一项实际反例修复了不同球队同名球员被合并统计的问题：统计、筛选与报告使用球队加姓名，同队同名仍需输入号码或稳定 ID。增加计算与筛选回归，并重新验证发布文件。最后两项回归属于发布收尾，不冒充已冻结版本的盲评证据。
