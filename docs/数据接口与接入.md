# 数据接口与接入

本文件对应 CourtLens v2 本机项目产品。完整输入例子见 [data/demo.json](../data/demo.json)，CSV 模板见 [templates/possessions.csv](../templates/possessions.csv)。这是项目自定义的中间格式，**不是主办方已公布格式**。正式适配须保留原文件、字典、版本与 SHA-256，不能把未知列猜成官方统计。

## 1. 三条真实数据接入路径

| 路径 | 输入与输出 | 调用方责任 |
|---|---|---|
| 人工新建 | 视频元信息、比赛信息和来源，生成完整视频占位回合。 | 编辑真实回合、球员、分值与时刻；占位不是识别结果。 |
| 回合 CSV | 已对齐的视频秒数、回合事件、可选指标，转换为 schema 1.0。 | 核对列含义、来源、Leverage 口径；不自动产生轨迹。 |
| 标准 JSON | 完整数据集，保留既有轨迹与注释。 | 完成原始字段映射、镜头校准、证据引用及媒体绑定。 |

三种网页入口均以待复核草稿开始。JSON 解读结果或 `replay.analysis.json` 不包含完整原始输入，不能代替标准数据集导入。

## 2. 标准 JSON 根字段

| 字段 | 类型与约束 |
|---|---|
| `schema_version` | 字符串 `1.0`。 |
| `provenance` | `kind` 为 `synthetic` / `official` / `user`；`label`、`source` 非空。`official` 只是提供者声明，软件不认证来源。 |
| `game` | `title`、`home`、`away`、`period`、`score` 为非空文本；主客队不能相同。 |
| `video` | `url` 非空，`duration` 为 0.001–14400 秒；`width`、`height` 为 1–32768 的整数。`sha256` 若给出，必须为 64 位十六进制字符串。 |
| `workflow` | 产品接入应提供 `{ "state": "draft" }` 或 `{ "state": "reviewed" }`；编辑后重新标为草稿。兼容边界见下文。 |
| `metric_definitions` | `xfg_pct`、`gravity`、`leverage` 三个非空文字定义，包含来源、单位和适用条件。 |
| `metric_semantics` | 已识别口径分别为 `shot_make_probability`、`supplied_metric`、`possession_win_probability_opportunity`。 |
| `possessions` | 1–200 个回合，按起始时间排序，不重叠，不超出视频。 |

指标语义不匹配时应修改正式适配器和分析逻辑，不能仅重命名、缩放或截断。非合成数据只要 `leverage` 非空，必须显式给出对应语义声明。`metric_definitions` 的自然语言说明不能替代此项机器可检验的声明。

纯分析接口为兼容旧 schema 1.0，允许省略 `workflow`；这不表示已完成审核。持久项目在创建、保存或恢复旧历史时会将缺失声明补为 `draft`，后台任务还会独立要求明确的 `workflow.state=reviewed`。新接入必须显式管理状态，第三方调用方负责在更改内容后撤销复核。网页已执行这一工作流；本机服务没有账户认证，复核状态不是带身份签名的审批凭据。

## 3. 每个回合的事件与空间数据

| 字段 | 约束与含义 |
|---|---|
| `id`、`title`、`clock`、`shooter` | 非空文本，`id` 在数据集中唯一。`clock` 只是节钟说明，不能作为视频时钟。 |
| `offense` | 必须与 `game.home` 或 `game.away` 完全一致。 |
| `start`、`end`、`shot_time` | 视频绝对秒；`start ≤ shot_time < end`。相邻回合可相接，不可重叠。 |
| `result_time` | 可空；给出时须在出手至回合结束之间。缺失时不在播放中宣布结果。 |
| `result` | `made` / `missed` / `unknown`。 |
| `points` | 0–4 的整数，表示此次投篮分值，不是实际得分。0 只用于草稿占位，会阻断产品导出。 |
| `metrics` | 必须含三项键，未知显式 `null`。xFG 与本项目 Leverage 为 0–1 有限数，Gravity 保留来源有限数值及单位。 |
| `source_refs` / `notes` | 来源引用至少一项，可包含源文件行、事件 ID 或链接；限制说明可为空数组。 |
| `camera_segments` | 至少一个 `{start,end,calibrated}`，区间有正长度、按时间排列、不重叠且位于回合内。`calibrated` 为布尔值。 |
| `tracks` | 可空。样本为 `{t,players:[{id,team,x,y}],ball:{x,y}}`；时间严格递增，同一帧球员 ID 不重复，同一回合球队归属一致。 |
| `annotations` | 可空。每项含 `id,start,end,kind,points,label,evidence_id`，来源细则见下一节。 |

空间坐标都是 **0–1 图像归一化坐标**。球场米数不能直接填入；先进行对应镜头的投影转换。轨迹每个回合最多 50000 个样本，整份输入最多 150000 个样本。只在同一已校准镜头的已知采样支持区间内插，缺失球员和采样范围外均不外推。

`annotations.kind` 为 `arrow` / `zone` / `label`；点数至少为 2 / 3 / 1，每点为 `[x,y]`。注释 ID 在数据集中唯一；`evidence_id` 不得占用内置指标、结果、轨迹或排序 ID，不得跨回合共用。标注是输入的解释材料，不会自动变成视觉检测证据。

## 4. 人工标注与追踪标注分别处理

省略 `origin` 的旧注释按 `tracking` 处理，其显示受原追踪镜头校准状态约束。人工画面标注须增加：

```json
{
  "origin": "manual",
  "frame_reviewed": true,
  "author_note": "已人工核对该时间段画面；静态标注，不是自动追踪。"
}
```

这是附加字段片段，不能单独作为完整注释提交。`author_note` 须为 1–500 字符的非空说明，`frame_reviewed` 必须严格为布尔 `true`。人工注释的整个有效区间必须包含在一个已声明镜头段内，不得跨镜头边界。

人工标注独立表述“操作者核对了这一段画面”，可以在原追踪未校准时单独显示。它**不修改** `camera_segments.calibrated`，不会启用轨迹图层、不跟随球员运动，也不证明标签里的因果判断。网页区域工具用两个角创建矩形四点；标准 JSON 可提供其他合法多边形。

## 5. CSV 适配契约

必填表头为 `id,title,start,end,shot_time,offense,shooter,points,result`。可选表头为 `result_time,clock,xfg_pct,gravity,leverage`。大小写和拼写须一致；重复表头拒绝，未识别额外列会给出忽略警告，字段多于或少于表头会报错。

以下只展示格式，队名、球员与数值均为虚构示例，不能当作真实比赛记录：

```csv
id,title,start,end,shot_time,offense,shooter,points,result,result_time,clock,xfg_pct,gravity,leverage
p01,示例回合,0,8,4,主队,球员甲,3,unknown,,第一节 10:00,,,
```

请求同时提供该视频的真实 `video`、`game` 和非空 `source`。上例的 `offense` 要与 `game.home` 或 `game.away` 一致，视频时长不得短于 8 秒。这里留下指标空值，避免把样例数值误作观测。

空字符串、`null`、`na`、`n/a` 可表示可空字段缺失；不接受 NaN、Infinity 或假零代替未知值。只要有非空 Leverage，请求须另加：

```json
{ "leverage_semantics": "possession_win_probability_opportunity" }
```

网页的口径确认勾选会明确发送这一声明。适配器不会仅因字段名叫 `leverage` 就替用户确认统计含义。球员累计 Leverage Score 或实际前后胜率变化不能直接输入此列。

CSV 文本限制 8 MiB、200 个回合，单字段限制 128 KiB；HTTP JSON 封装本身也受 8 MiB 请求限制。报错路径中的 `csv.row[N]` 和来源引用里的行数，是 **CSV 记录结束的物理行号**。引号内多行文本会使一条记录跨行，因此不是第 N 个回合。CSV 生成空轨迹、空注释及未校准镜头，不自动把比赛倒计时转换成视频秒数。

## 6. 时钟转换与视频绑定

`core.calibration.time_map(t, anchors)` 在多锚点包围区间内进行线性映射，拒绝外推。比赛倒计时应先转换为特定节次内单调增加的事件序列；暂停、切回放和广告之后重新分段。不要使用整场统一 offset。

`core.calibration.homography` 使用同一球场平面的四组对应点，`project` 投影其他场地点。切镜后重新校准，至少另留两个未参与拟合的检查点评估误差。平面映射不能重建空中球的高度。

标准 JSON 可以先没有 `video.sha256`，但质量检查会阻断成片导出。持久导入时服务逐字节计算指纹，检查实际尺寸与时长，将 `video.url` 改为项目媒体路由，并创建新版本。尺寸须完全一致，数据声明与容器时长容差 0.1 秒；另外核对画面轨的实际覆盖，若音轨尾部会使导出请求不存在的视频帧则拒绝导入，需先裁齐尾部后重新校准。WebM 缺少画面时长字段时读取画面包时间戳；无法验证时拒绝。当前拒绝需要非零旋转的媒体；单视频最大 512 MiB。实际浏览器可播放性还取决于编码。

复盘播放另核对绑定，核验未完成或失败时清空同步叠加与字幕，暂停证据跳转。独立阅读数据不代表其与当前画面匹配。SHA-256 证明绑定字节，不能证明事件、指标或授权正确。命令行 `tools/bind_media.py` 同样不负责语义或空间校准。

## 7. 本机 HTTP API

地址默认 `http://127.0.0.1:8765`。项目 ID、任务 ID 为服务生成的十六进制 UUID；项目 `revision` 从 1 递增，时间为 UTC 字符串。以下表中的请求均为 JSON，媒体上传除外。

| 方法与路径 | 请求 / 响应核心 |
|---|---|
| `GET /api/health` | 服务状态、版本。 |
| `GET /api/capabilities` | FFmpeg、FFprobe、Pillow、`render_available`、`render_python`、`tts_available`、`mode=local`、最大媒体字节数；网页云能力为未配置。 |
| `GET /api/demo` | 合成演练数据集。 |
| `POST /api/new-dataset` | `{video,game,source}` → `{dataset}`，生成草稿占位。 |
| `POST /api/adapt/csv` | `{csv,video,game,source,leverage_semantics?}` → `{dataset,warnings}`。 |
| `POST /api/quality` | `{dataset}` → `{report}`，含检查、阻断项、警告、覆盖和 `export_allowed`。 |
| `GET /api/projects` | `{projects:[项目摘要]}`。 |
| `POST /api/projects` | `{name,dataset}` → 201 `{project}`。 |
| `GET /api/projects/{id}` | `{project}`，含完整数据集与持久媒体信息。 |
| `POST /api/projects/{id}/save` | `{name,dataset,expected_revision}` → `{project}`。 |
| `GET /api/projects/{id}/history` | `{revisions:[{revision,created_at,name}]}`。 |
| `POST /api/projects/{id}/restore` | `{revision,expected_revision}` → `{project}`；将旧内容恢复为新版本。 |
| `POST /api/projects/{id}/media` | 原始视频字节 → `{project}`；头部契约见下文。 |
| `GET /api/projects/{id}/media` | 受控媒体响应，支持单段 HTTP Range。 |
| `POST /api/projects/{id}/export` | `{expected_revision,audience,voice?}` → 202 `{job}`；`voice` 默认 `false`，必须为布尔值。 |
| `GET /api/projects/{id}/jobs` | `{jobs:[任务记录]}`。 |
| `GET /api/jobs/{id}` | `{job}`。 |
| `POST /api/jobs/{id}/cancel` | `{}` → `{job}`；最终状态请求幂等。 |
| `GET /api/jobs/{id}/files/{name}` | 完成任务的 `replay.mp4`、`replay.vtt`、`replay.analysis.json`，配音成功时另有 `replay.voice.json`，作为附件下载。 |
| `POST /api/analyze` | `{dataset,audience}` → 排序、证据、解说、cues、trace。 |
| `POST /api/ask` | `{dataset,question,possession_id,audience}` → 本地受限回答、证据 ID、模式、警告、trace。 |

`audience` 为 `fan` 或 `analyst`。分析、适配与质量接口本身不保存项目；调用方需使用项目保存接口。创建、保存、恢复或上传成功后，应立即采用响应中的新 revision；不得连续重复使用旧版本号。导出绑定请求时的已保存版本，继续编辑不改变已冻结输入。

任务响应包含 `voice`、`status`、`progress`、`progress_label`、`error`、`revision`、`media_sha256` 和 `files`。文件记录含 `name,url,bytes,size,sha256,content_type`。配音任务的渲染阶段按真实帧数映射到 0–0.8，语音阶段按真实完成字幕条数映射到 0.8–0.98，核验通过后为 1；不要将整段进度都解释为视频帧百分比。

`voice=true` 仅在 macOS 且本机 `say` 可用时受支持，以同步字幕生成中文音轨，不调用云服务，不保留原音。能力探测不代替实际语音合成核验。不可用时返回 503 `tts_unavailable`，工具失败、过密字幕或取消时不提供无声中间成片，不能暗中降级成 `voice=false`。

媒体上传使用原始字节，**不是 multipart 表单**。提供 `Content-Length`、整数 `X-Expected-Revision`、经 URL 编码的 UTF-8 `X-Filename`，可给 `Content-Type: video/mp4` 或对应类型。格式以服务实际探测为准，不能靠扩展名绕过核验。不支持分块请求体。没有额外任意文件路径参数。

## 8. 错误、审核和调用方注意事项

| 状态 | 常见含义与处理 |
|---|---|
| 400 | JSON、字段、CSV 行、媒体、审核或质量不通过；阅读 `error`、可选 `path` / `code` 后修复输入。 |
| 403 | 非本机 Host 或不允许的请求来源。 |
| 404 | 项目、历史、媒体、任务或文件不存在。 |
| 409 | revision 冲突、绑定损坏、任务未完成或工作区占用；保留草稿并重新读取状态，不自动覆盖。 |
| 413 | JSON 超 8 MiB 或视频超 512 MiB。 |
| 415 | JSON 路由未使用 `application/json`。 |
| 429 | 最多四个等待任务已满；等待或取消。 |
| 503 | 导出或配音依赖缺失、服务关闭或当前平台不支持必要服务锁。 |

质量状态不是篮球准确率。显式草稿、占位球员、零分占位或缺少指纹会阻断导出；缺失指标、结果时刻、轨迹、校准或覆盖则给警告。持久导出还独立要求 `reviewed`、注册媒体、版本一致和可用依赖；直接调用质量接口的 `export_allowed=true` 不是完整导出授权。来源始终按自我声明处理，不能据此声称已获官方认证。

JSON 请求不超过 8 MiB，严格拒绝非有限数、重复对象键和不合法路径。工作区不直接静态暴露，完成文件只按白名单下载。接口没有用户管理、TLS 和多租户权限，不能直接对公网开放。完整任务恢复、备份和依赖说明见 [产品架构与运维](产品架构与运维.md)；实测结果见 [最终验收报告](最终验收报告.md)。
