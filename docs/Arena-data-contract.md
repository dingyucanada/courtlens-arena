# CourtLens Arena v4 数据契约

本文件对应 `pro/model.mjs`、`pro/analytics.mjs`、`pro/calibration.mjs`、`pro/render.mjs`、`pro/director.mjs` 和 `pro/export-video.mjs` 的实际接口。它是本产品的输入约定，不是赛方尚未公布的官方字段字典。正式素材接入时必须先核对字段定义、单位、时间与坐标，再建立适配映射。

## 1. 输入种类与保留原则

| 输入 | 入口 | 保存方式 |
|---|---|---|
| 逐回合 JSON | 顶层 `plays` 数组，或直接给记录数组 | 转为 Arena 项目；每条原记录另存 `sourceRecord` |
| CSV | 带表头；界面可映射 `start`、`end` 等字段名 | 严格处理引号、转义、换行与列数；保留导入行作为来源记录 |
| 旧版比赛数据 | 顶层 `possessions`、`metric_semantics`、`metric_definitions` | 保留定义和逐回合原记录；画面轨迹放入 `screenTracks` |
| Arena 备份 | `schema: "courtlens-arena/1"` | 检查 ID、修订号、引用、时间与容量；补齐缺失的编辑容器 |
| 视频 | 浏览器可解码的本地 MP4 / WebM 等文件 | 视频字节保存在当前浏览器的 IndexedDB；项目 JSON 只保存元数据与绑定信息 |

`sourceRecord` 是原始输入快照。时间转换、编辑、复核和导出不覆写这个快照。来源标签 `official`、`measured` 等来自提供者声明，不代表软件已经认证该来源。仅靠文件名称、球队名称或来源标签，不能证明素材就是赛方提供的原件。

备份缺失 `notes`、`calibrations`、`playlist`、`activity` 时会初始化为空数组。已提供但类型错误的 `{}`、`null` 等容器不会被静默修成合法数据。备份不包含原视频字节，迁移到另一浏览器或另一网址后须重新绑定保留的原片。

## 2. 实际容量与验证范围

| 项目 | 当前限制 |
|---|---|
| CSV / JSON 输入 | 16 MiB，按 UTF-8 字节计算 |
| 本地视频 | 512 MiB，须有正的有限时长与尺寸 |
| 单项目回合数 | 2,000 |
| 单回合时长 | 最多 600 秒，`end > start >= 0` |
| 单回合每组轨迹 | `tracks`、`screenTracks` 各最多 10,000 帧 |
| 项目轨迹总量 | 两组轨迹合计最多 120,000 帧；这是编辑项目的有效上限 |
| 单帧球员数 | 最多 20 |
| 项目 / 回合 ID | 项目 ID 为 1–500 字符；回合 ID 为 1–120 字符且项目内唯一 |
| 项目名称 / 修订号 | 名称 1–300 字；`revision` 为非负安全整数 |
| Agent 问题 | 最多 1,200 字符 |
| 浏览器故事录制 | 片单总长最多 180 秒、最多 2,000 个片段；输出画布 1280 × 720 |

分析内核自己的总轨迹容量高于编辑项目，但导入与保存仍受上述 120,000 帧限制。上述限制只说明可接收的结构与资源范围，不说明测量精度。无效身份、重复采样、缺口与越界坐标还会在分析或渲染阶段被丢弃或暂停，并给出具体提示。

## 3. 最小输入示例

下面的秒数仅演示数据结构，不代表任何真实 NBA 比赛。未知指标、未知结果与未提供的事件保持为空，不生成示意球员位置。

```json
{
  "name": "用户导入比赛",
  "provenance": {
    "kind": "unverified",
    "label": "待复核的提供者记录",
    "source": ""
  },
  "video": null,
  "metricSemantics": {},
  "metricDictionary": {},
  "plays": [
    {
      "id": "p01",
      "title": "待复核回合",
      "start": 10,
      "end": 20,
      "shotTime": null,
      "resultTime": null,
      "clock": "",
      "team": "HOU",
      "player": "",
      "shotValue": null,
      "outcome": "unknown",
      "metrics": {"xfg_pct": null, "gravity": null, "leverage": null},
      "tracking": {"kind": "unverified", "coordinateSystem": "unknown", "timeBase": "video"},
      "tracks": [],
      "screenTracks": [],
      "cameraSegments": [],
      "annotations": [],
      "sourceRefs": [],
      "reviewed": false
    }
  ]
}
```

没有官方字典时，语义字典保留 `{}`，不预填猜测的定义。若保存一个未知口径的实际读数，可以在指标记录中明确使用 `semantics: "unknown"`；该读数允许查看，不能据此做专业归一化或比较。

## 4. 缺失值、字段优先级与指标语义

`start`、`end` 必须是有限数字。JSON 的 `true`、`false`、数组和对象不会被当成 1、0 或时间。CSV 的普通十进制数字字符串可转换；空白可选值转换为 `null`；必填值为空则拒绝导入。真正的数值 `0` 保留。

字段映射指定的列优先，其后是标准字段，再后是兼容别名。选择依据是字段是否存在，不是是否为真。`shotTime: null` 不会被 `shot_time: 17` 复活；嵌套 `metrics.xfg_pct: null` 不会被顶层同名数值填补。备份遗留的事件别名正规化到标准字段，原始内容仍可从 `sourceRecord` 追溯。

未知 `shotTime` 始终保持 `null`，不得以 `end` 伪造出手时刻。仅提供合法 `resultTime` 的回合允许普通解读，结果在自己的时间锚点可用，但不能进行出手前冻结；没有出手锚点的指标只在可用时刻作为输入读数，不能生成出手几何或出手标记。

`outcome` 仅有 `made`、`missed`、`unknown`。空值、未识别的字符串或未观察到的结果导入为 `unknown`；它们不意味着投丢。`shotValue` 只允许 2、3 或 `null`。

指标对象保存 `value`、`semantics`、`unit`、`definition`、`provenance`，并保留提供者的 `range`、`availableAt`、版本号等附加字段。例如，`value: null` 的记录仍可保存官方定义；数值栏显示未提供。不会将它改成 0。

| 语义情形 | 本产品处理 |
|---|---|
| 已声明的单次出手命中概率 | 按原读数保存；在明确概率定义下可计算 `1 - p` 作为本地难度表达，另标派生来源 |
| 明确的难度指标 | 保留方向、范围与定义；不因名字相似就改为命中概率 |
| Gravity 无可比较范围或单位 | 可显示来源读数；不借最近防守距离替代它，不强行统一尺度 |
| Leverage 未知或为球员累计指标 | 保留原定义；不改成 0–1 回合胜率机会差 |
| 多回合指标定义或单位不兼容 | 保留各自数值；阻断不成立的比较、归一化或排名分量 |

本标准中的标量 `xfg_pct` 指 0–1 概率，不能直接塞入 42 来表示 42%；其他提供者的同名字段应先核对并显式适配。旧版导出保存原 `metric_semantics` 和 `metric_definitions`，同时附带完整 `metric_records`。无法用单一旧字段表达的混合口径会被拒绝，应该改用 Arena 项目备份。

## 5. 一套视频时钟，两种轨迹空间

事件 `start`、`end`、`shotTime`、`resultTime`，指标的 `availableAt` / `time` / `t`，人工图形及镜头区间都使用**视频绝对秒**。比赛钟如 `Q3 07:41` 仅是上下文。它不是可直接播放的时间，也不能用全场一个固定差值消除广告、暂停、回放与节次重置。

`tracks` 是球场空间；其 `tracking.timeBase` 可明确声明为 `video` 或 `possession`。导入和备份正规化在明确 `possession` 时只做：

```text
tracks[i].t = play.start + 原回合经过秒
tracking.timeBase = "video"
tracking.sourceTimeBase = "possession"
```

这一步**不改 `screenTracks`、事件或指标时间**。`screenTracks` 使用独立的视频绝对秒。原来采用其他时钟的画面点或指标须先单独建立经核对的映射，不随球场轨迹盲目平移。保留的源记录不参与第二次转换。

`mapTime` 在已核对锚点之间做分段线性内插。源锚点必须唯一，目标视频秒须递增；多锚点范围外禁止外推。重复比赛钟需要节次/镜头分段，分段边界不能跨越内插。默认只有一个锚点时仅映射这个精确点；同步界面显式启用 `singleAnchorOffset` 时，可由操作者声明固定偏移 `video - source`。这项声明不能证明全片没有时钟漂移、暂停或回放；复杂转播需要多段锚点。重新同步后要重新核对片单、字幕编辑与镜头标定。

| 轨迹 | 必要空间含义 | 能做什么 |
|---|---|---|
| `screenTracks` | 原视频画面上 0–1 归一化 `x,y`；每帧含 `t,players` | 画面点、标签、像素关系与有界路径；不产生真实英尺距离 |
| `tracks` | 明确球场坐标系、单位、场地尺寸和球员身份 | 在可信数据条件下计算距离、连续采样窗口、同身份的空间变化；独立球场视图 |
| 未知坐标 / 未提供轨迹 | 无可信空间位置 | 继续看视频、读指标和人工标注；不伪造球员点或声称发现空档 |

球场单位建议使用 `ft` 或 `m`，并给出实际 `court.width`、`court.length`、篮筐位置与坐标方向。归一化球场坐标只有在声明物理场地范围后才有物理意义；原图坐标不能被默认为球场坐标。相同球员 ID 可能跨队重复，因此身份使用球队与球员 ID 的组合。

路径只在相同身份、同一镜头且缺口不超过 `maxGap` 时内插，默认 `maxGap = 0.75` 秒。缺失身份不补点，切镜不连线，重复时间不猜一个“正确帧”。这是一种有界插值，不是视觉检测。

## 6. 原视频身份与逐镜头平面标定

本地视频绑定记录 `video.id`、`name`、`size`、`type`、`duration`、`width`、`height`、`sha256`。首次没有历史指纹时，需要操作者确认数据对应这份原片；同字节指纹可确认重新选入的是相同文件，不证明该文件来自 NBA 官方。

已记录指纹而新文件字节不同，会关闭旧画面轨迹与图形，清除镜头标定并撤销回合复核。球场记录仍可保留，但须重新对齐新片的时间。浏览器存储和项目修订一起保存；更换素材后不借用旧画面坐标继续叠加。

画面轨迹由提供者直接给出时按画面坐标显示。球场坐标叠加到原视频则必须有有效的平面标定：4 对对应的球场点与归一化画面点，或来源提供的 3×3 单应性矩阵；并记录 `source`、明确的 `reviewed` / `calibrated`、区间 `start,end` 和适用 `segmentId`。`false` 的复核标志不会被其他字段覆盖。

`cameraSegments` 存在时，当前时刻必须落在唯一的区间，且其 `calibrated` 为 `true`，才显示自动画面层。没有镜头分段时，画面轨迹按输入声明显示，并保留“未提供镜头分段”的提示；不能因此宣称所有切镜均已识别。

四点拟合检查的是配对与数值可解性。退化、共线、重合、无穷投影点会拒绝。另行提供的 `checkPoints` 可计算独立点 RMS 与最大误差；没有足够独立点时只给提示，不发布虚构精度。固定平面的单应性不能恢复空中篮球的三维位置；镜头移动、变焦或切换后必须重新分段标定。

## 7. 证据、字幕与成片时钟

每条分析证据包含可追溯的 ID、回合归属、字段、来源类型和时间。缺失指标可用时间时保守地视为回合结束可用；提供了可用时间则不得提前显示。结果必须等待独立 `resultTime`；没有结果锚点的显式时刻视图不会提前宣布命中/投丢。

片单允许重复使用同一回合，但每次裁切是独立片段。裁切不能超出原回合，不能引用不存在的回合。字幕先检查源时钟，再裁切并映射到连续成片时钟；保留 `sourceStart`、`sourceEnd`。若存在 `relativeStart` / `relativeEnd`，导出计划同步更新为成片时间，避免残留源回合偏移。

WebVTT 拒绝非有限、倒置、越界、乱序或不足 1 ms 的区间。正文按字面文字处理 `&<>`，保留引号，并消除可注入新记录的换行/控制字符。报告中的名称、修订号、来源、文本和证据均进行 HTML 转义。

人工改写保留 `origin: "manual"` 与 `originalText`；报告显示“人工编辑 · 未自动认证”及原引擎文句。保留 `evidenceIds` 只是候选引用，不证明这些证据支持改写后的句子。审核标志表示操作者核对，不是系统认证篮球因果。

浏览器录制使用不可变项目/字幕/图层快照。支持解码帧回调时，叠加按 `mediaTime` 对齐；退回页面动画时钟时明确报告近似同步。MediaRecorder 是实时编码器，片单规划时长不等于已经测出的文件时长。导出还记录帧时间、帧数、采集模式和录制耗时；实际文件须独立播放检查。当前输出含画面、图层和字幕，没有音轨；语音试听不代表成片配音。

## 8. 模型与来源的信任边界

静态网页可运行本地证据引擎，但这条路径不是语言模型。可选本机服务接入 Ollama 或 AWS Bedrock，模型调用 `search_plays`、`read_evidence`、`publish_story`，选择已存在的声明 ID；公开文字与数字由服务端编译，不直接接受自由生成的篮球结论。

服务端检查结构、有限数值、引用归属与时间关系，不重新测量原视频、不重算浏览器全部几何分析、不认证官方来源。真实模型是否连接成功，必须以实际调用与执行记录为准；模拟协议测试不能代替它。GitHub Pages 不运行这个服务端，也不保存云密钥。

正式数据接入还要确认使用权限、采样定义、完整防守名单、身份可靠度、单位和指标版本。缺少这些条件时缩小解释范围。一个回合结果、一个厂商案例或使用训练科技，均不能单独证明战术选择、训练处方或夺冠因果。
