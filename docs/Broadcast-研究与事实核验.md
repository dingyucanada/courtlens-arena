## 3. 开源感知：采纳组件，拒绝“装好即完整可用”

### 保留并收窄：RF-DETR + SAM2 + 聚类 + OCR

Roboflow自己的篮球教程确实使用专门微调的RF-DETR、多目标SAM2、SigLIP/UMAP/K-means与号码识别；报告T4约1–2 FPS。它的主题是球员检测、跟踪、身份识别，不能据此承诺自动投篮事件、真实战术因果或官方高阶指标。通用RF-DETR权重不是那份十类篮球微调权重。原文SmolVLM2初始号码准确率56%，且有进一步微调及ResNet方案，说明“装OCR就认全人”不成立。[作者教程](https://blog.roboflow.com/identify-basketball-players/)

具体采纳条件：只对已选关键事件窗口运行；锁定模型ID/权重hash/依赖版本；检测类别逐项与模型metadata核对；OCR输出是候选号码，必须结合当场阵容、球队和时间投票绑定；遮挡或冲突时保持unknown。聚类标签0/1没有球队语义，需要锚点映射；同队同号码并非跨赛季唯一身份。镜头切换后SAM状态不能盲目续用，重入场目标要重新核验。

**1–2 FPS是处理吞吐量，不是建议的视频采样率。** 例如48秒×30 FPS=1440帧，若全帧流水线持续1–2处理帧/秒，纯处理约12–24分钟；这是算术估算，尚未计下载、初始化、OCR、重试和渲染，也不是本工程实测。10秒定向窗口可显著缩小量，但仍须记录实际帧数与耗时。不能用“处理1 FPS”声称“几秒处理完48秒片”。

许可采用版本级台账即可，不做泛泛法律扩张：

| 状态 | 组件 | 核验结果与接入约束 |
|---|---|---|

**修正部署假设：GPU流水线不能默认塞进Lambda/Fargate。** Fargate当前不支持GPU；它可用于CPU渲染，但不继承T4吞吐量。若GPU服务/权限/配额不具备，CV增强必须明确unavailable，仍可采用真实视频模型与人工复核帧的路径，不能输出伪轨迹。[AWS Fargate FAQ](https://aws.amazon.com/fargate/faqs/)

**修正投影承诺：** 平面映射适合落地脚点及球场线；球在空中、起跳身体中心都不在球场平面。平移/变焦、切镜头后旧矩阵失效。首版只在能校验锚点误差的短区间画空间示意；不能仅凭球员框中心计算离筐距离或空中球速。

## 4. 视频与模型：新主干的通过条件

**有条件保留**“视频语义先提议→对候选窗口取帧/CV→严格绑定→最多三个故事”。它避免对整回合做高成本高风险全量感知。三条故事是上限，不是填满目标；证据只支持一条时就输出一条。

必须补四个限制：

1. 视频理解输出只有proposal权限。每个事件带候选区间与不确定性，不能自行生成官方值或最终轨迹；CV取证可否决它。事件窗口前后留余量，避免模型自己只挑“支持自己”的一帧。
2. “Bedrock”是平台，不是视频能力声明；“Qwen235B”也不足以推断视觉、视频、工具调用能力。用实际modelId做小片真实调用探针，记录输入模态与响应；文本模型只做已验证证据的组织。没有视觉模型则视频理解阶段blocked，不能模拟成功。
3. 整段视频API仍可能内部稀疏采样。AWS Nova文档示例中，Lite/Pro对16分钟以内的视频使用1 FPS；这能帮助场景概述，不能保证捕捉亚秒出手/触球。因此“禁止抽帧”错误；应区别全局语义抽样和短窗口密集证据。[AWS视频输入文档](https://docs.aws.amazon.com/nova/latest/userguide/modalities-video.html)
4. 固定最大输入时长/大小、窗口数、采样帧数、模型轮数和重试次数；实测记录wall time、输入/输出tokens、CV帧数、GPU/CPU秒、TTS字符与音频秒。费用按实际模型、区域与计价日计算，未实跑不承诺每回合价格。模型上下文“大”不意味着稀疏采样没有丢动作。

Strict绑定必须同时通过：源片hash、shot/possession ID、比赛/赛季、球员身份、指标粒度、源字段、单位、源PTS/镜头ID、输出时间映射和证据是否可用于当前叙事时点。只验证JSON结构或“引用ID存在”不够。

## 6. 最少高价值反例测试

以下8组应先于新增人设/图表。通过目标是反例真的触发拒绝或降级，而非编写一组永远返回成功的演示测试。

| # | 输入/故障 | 必须发生的行为 |
|---|---|---|
| 1 粒度陷阱 | 仅东契奇赛季xFG表；另有无官方事件值的出手视频 | 不生成“本球39.6%”；背景卡有赛季标签，事件卡明确无值，仍可讲有视频证据的动作。 |
| 2 数学/口径陷阱 | xFG18%、季均39.6%、GRAV−5但画面贴防、TOT LVG3.3、DEF DIST30无单位 | 拒绝“难一倍/被放空/胜率+3.3%/0.762米”；56.9−46.6显示10.3个百分点。 |
| 3 历史身份 | 历史独行侠片+后续湖人球员表；另一人号码77；OCR模糊 | 不凭队名或号码硬认；gameId/date阵容不符即needs_review；未来背景不进入出手前盲看。 |
| 4 时钟与重复镜头 | 同一进球直播+慢动作回放，随后切场边；源PTS≠输出PTS | 不重复计事件，不把球员框漂到观众身上；慢放字幕和证据回跳正确，切镜头隐藏失效图层。 |
| 5 稀疏视频遗漏 | 出手发生于相邻1秒采样点之间；语义模型误报传球 | 触发短窗口取证或unknown；不凭模型高置信度造精确出手毫秒；取证允许否决proposal。 |
| 6 空中投影/遮挡 | 球员起跳、篮球飞行、相机变焦、球衣不可见 | 不拿框中心/空中球做场地距离；投影误差超阈值隐藏；身份冲突保留unknown且可复核。 |
| 7 假自动成功 | 无模型权限、无权重、GPU不可用、外部API超时/429 | 对应阶段blocked/unavailable/failed；不返回合成轨迹或样例故事作为当前素材结果；重复执行有上限，保留上次有效版本但不冒充本次。 |
| 8 交付换片 | 新视频字节但同文件名，改单位或人工修正球员，随后云调用失败 | 推理/渲染缓存正确失效；CloudFront展示绑定版本；真实Agent调用有输入hash/资源身份，不能拿本地或旧素材调用算验收。 |

## 7. 独立评审标准

**可以交给Sol开发的标准：** 上述修正进入数据契约、状态机与旁白规则；实现真实provider接口、定向证据适配器和降级分支；避免把缺账号/缺权重的集成标为已完成。现在就可开发，不需要等所有外部条件就绪。

**可称本地功能完成的标准：** 至少一段非调参样片跑通真实视频理解→证据→故事→成片；逐句事实可回跳，所有显式数字有单位与粒度，8组反例通过。人工修正记录清楚；展示故事覆盖率、unknown数和人工改动量，而不是用虚构准确率打分。

**可称正式参赛就绪的标准：** 正式资料确认Agent/区域/模型/输入字典；在指定账号真实CDK部署，指定Agent服务调用当前输入，CloudFront从外部可播当前版本；考试对应素材已标识且可追溯。任何核心项未知时，报告“实现已具备/正式验证待办”，不可写“保证拿35分”或“已满足全部赛规”。

本审查没有认定最后排名、特定片段战术或模型精度；这些必须由真实素材与运行证据决定。
