# CourtLens Arena v4.0 · 使用与验收

文档日期：2026-09-28。适用版本：Arena v4.0；Studio v3 和原 SQLite / FFmpeg 工作台另有手册。

Arena 的交付主线是：**比赛视频与深度数据 → 校准 → 有证据的回合分析 → 叠加与解说 → 复核 → 可播放成片。** 当前内置比赛、球员轨迹和指标均为合成演练；标注 HOU / DAL 是赛题场景表达，不是实际球队比赛记录。

[公开 Arena](https://dingyucanada.github.io/courtlens/) · [源代码](https://github.com/dingyucanada/courtlens) · [产品演示 PPT](CourtLens-Arena-产品与参赛方案.pptx) · [浏览器有声成片](../media/arena-browser-story.mp4) · [数据合同](Arena-data-contract.md)

## 1. 选择运行入口

| 入口 | 可用内容 | 保存位置 |
| --- | --- | --- |
| GitHub Pages 根首页 | 四工作区、导入、校准、本地证据分析、叠加、问答、复核、浏览器录制与资料下载。 | 当前浏览器 IndexedDB；新成片在当前页面生成并下载。 |
| 本机 `/arena/` | 上述浏览器功能，加可选模型接口、macOS 中文配音、受控 HTTP 成片保存。 | Arena 项目仍在浏览器；成片库在本机 `workspace/arena_artifacts/`。 |
| 本机 `/studio/`、公开 `studio.html` | 保留的 Studio v3 流程。 | 独立浏览器数据库。 |
| 本机 `projects.html` | 原 SQLite 持久项目、人工标注、FFmpeg 后台任务。 | 独立 `workspace/` 数据库与媒体目录。 |

GitHub Pages 不运行 Python、配音或语言模型服务。Arena、Studio 和 SQLite 工作台不自动同步项目。公开 `pro/` 目录只有模块，不是网页入口。

在项目根目录启动：

```sh
python3 tools/launch.py --port 8765
```

打开 `http://127.0.0.1:8765/arena/`，停止服务按 Ctrl+C。`python3 tools/launch.py --help` 已实际核验；显示 `--port` 与 `--workspace`。原工作台渲染解释器可通过 `COURTLENS_RENDER_PYTHON` 配置。启动器先构建静态内容，再运行只绑定回环地址的本机服务，不安装依赖。

浏览器工作流无需 Node、FFmpeg 或 Pillow。额外能力按需使用已安装工具：

| 额外能力 | 需要的工具 |
| --- | --- |
| Arena 本机成片库 | FFprobe，用于实际媒体格式、时长与编码核对。 |
| Arena 可选中文 MP4 配音 | macOS `say` 的 Tingting 语音、FFmpeg、FFprobe。 |
| 共享 Arena 内核离线 MP4 | Node 与 `@napi-rs/canvas`、FFmpeg / FFprobe、可用中文字体。 |
| 原 SQLite / FFmpeg 工作台导出 | FFmpeg / FFprobe、带 Pillow 的 Python 渲染解释器。 |
| 模型 Agent | 已安装并配置的 Ollama 工具调用模型，或 boto3 与具有模型权限的 AWS 账户。 |

本机配音当前不提供 Windows 等价实现。能力检测只报告已发现的工具和配置，不代表真实导出或模型调用已经成功。

## 2. 先体验合成演练

首次打开且没有已有项目时，Arena 自动载入三回合、36 秒的合成演练。以后恢复当前来源地址下最近的未归档项目。

1. 在“智能观赛”选择一个回合，播放并开关图层。
2. 在“轻松看懂”和“专业解读”之间切换；同一证据以不同深度表达。
3. 点击指标，查看其来源、定义、单位和可用时间；点击解说证据，查看回合与字段引用。
4. 点击“查看计算与覆盖率”，了解回看排序使用了什么数据。它是有定义的选片规则，不是训练得到的 NBA 关键回合准确率。
5. 在出手前暂停，点击“结果揭晓前”，先选择直接出手、继续寻找传球或信息不足，再揭晓后续。
6. 进入“战术实验室”比较回合，随后在“故事导演”加入片单、复核和制作。

合成演练含 xFG 38%、71%、62% 等示例值。它们证明系统如何处理字段，不是任何真实球员或球队的表现。H5 的示例空间窗来自该合成轨迹的实际计算：阈值 6 ft，观察区间 26.5–29.5 秒，7 个采样，最大间隔 0.5 秒。该 3 秒窗只是采样证据，不保证窗口之间持续空位，也不等于传球必然成功。可复现统计见 [演练统计](arena-assets/deck-demo-statistics.json)。

## 3. 建立自己的比赛项目

打开“比赛项目 → 新建比赛”，填写名称。项目之间的视频和数据独立。归档保留原内容；可以在归档列表恢复。

在“素材与校准”中导入 CSV、逐回合 JSON 或 Arena 项目备份。先下载接入模板，再根据真实提供者的字段字典填写。字段映射不能只看名称：`difficulty` 可能是概率，也可能是另一个难度评分；`leverage` 也可能是回合量或累计量。完整约定见 [Arena 数据合同](Arena-data-contract.md)。

导入预览后确认保存为独立项目。导入不会证明来源真实，也不自动完成复核。少量自有视频可人工新增回合，填写视频起止、出手与结果时刻、球员及结果；人工新增不是自动识别。

主要输入限制：

| 项目 | 限制 |
| --- | --- |
| CSV / JSON 文件 | 16 MiB；最多 2,000 个回合。 |
| 单回合 | 最长 600 秒；ID 必须唯一。 |
| 轨迹 | 单回合 `tracks` 与 `screenTracks` 各最多 10,000 帧；项目合计最多 120,000 帧；每帧最多 20 个球员。 |
| 视频文件 | 512 MiB；需当前浏览器实际可解码。 |
| 概率字段 | 0–1；0 是有效值，空值是未提供。不能填写 62 来表示 62%。 |

输入结构错误、无限数、错误单位或时间越界会阻止保存并给出原因。来源原记录会保留，不把正常化字段冒充原始记录。项目备份不含视频字节。

## 4. 绑定视频与核对时间

在“绑定比赛视频”选择本地文件。系统读取尺寸、时长与 SHA-256，并把 Blob 与项目事务一起保存在浏览器。当项目没有原指纹时，需要人工确认数据来自同一原片。

同一指纹表示字节一致。绑定不同视频会撤销复核，清除旧画面坐标轨迹、人工标注与镜头标定，避免将旧坐标画到新视频。球场数据也应重新核对其时间和来源；软件不替你确认它来自同一场比赛。

所有工作时刻使用**原视频绝对秒数**。节次与比赛钟可作为标签，但不能直接当作视频秒数。若提供者已输出视频时间，无需设置同步锚点。

确需同步时，在“设置同步锚点”逐行填写 `源时间,视频秒数`：

```text
0,5
120,125
```

确认画面后再应用。单锚点是人工声明的固定偏移；多锚点在覆盖范围内分段线性映射，不自动外推到范围外。暂停、剪切或回放插入需要额外锚点。

同步会转换当前项目回合、轨迹、标注、镜头区间和指标可用时间，保留来源原记录；旧解说编辑、片单和标定会重置。不要对已转换的项目重复应用同一映射。先备份，必要时从修订历史恢复；恢复会形成新 revision。

## 5. 镜头校准与叠加

两类坐标分别处理：

- `screenTracks` 是视频画面的归一化坐标，可直接叠加，不能据此声称实际英尺距离。
- `tracks` 是有单位和场地尺寸的球场坐标，可计算球场几何；画回视频需要对应镜头有效的平面标定。

在稳定镜头暂停，点击“标定当前镜头”，按**左下、右下、右上、左上**依次选择所声明球场矩形的四个地面角。填写实际宽度、长度和镜头起止。默认 50 × 47 ft 只是半场起始值，须与实际坐标区域一致；不能把全场 94 ft 数据套用到半场区域。

保存之前核对四个地面点、坐标轴和镜头区间。四点求解的是地面平面投影，不用于球员头部、手、空中篮球或三维投篮弧线。镜头移动或切换后需要新标定；提供了镜头段时，标定区间须完整落在一个镜头内。

四个拟合点本身不能证明精度。另选球场线交点检查投影偏差；如有独立检查点数据，可以保存 RMS 等误差证据，缺失时不显示虚构精度。

轨迹缺口超过阈值、同一时刻重复记录、身份不连续、镜头冲突或名单不完整时，对应连线、空间窗或防守解释会受到限制。球员身份由队伍和 ID 共同决定，不凭最近位置猜人名。

## 6. 智能观赛与战术实验室

“智能观赛”把读数、解说和叠加放在同一回合时间轴上。可用速度包含 0.5、0.75、1 与 1.5 倍。逐步跳转约 33 ms 是浏览器操作近似，不保证任意编码视频恰好前进一帧。

“结果揭晓前”以冻结时刻作为信息边界：未来结果、未到可用时刻的指标和后续轨迹不会提前用于判断。没有可用时间的输入采取保守展示，不把赛后指标包装成出手前信息。揭晓是比较证据的交互，不评分为“最优决策”。

开启冻结需要有效且无矛盾的 `shotTime`。缺失出手时刻时不以 `end - 0.2` 代替；仅有结果时刻也不能证明画面处于出手前。已有出手时刻但结果时刻非法、越界或与出手矛盾时同样拒绝；只有有效出手时刻、结果缺失时可以启动，结果仍保持未知。有效指通过字段和时间关系检查，不构成来源认证。

普通解读同样保留未知出手时刻：不生成末尾“出手采样”或虚构出手解说；仅有合法 `resultTime` 的记录可以正常导入和解读结果，仍不能开启出手前冻结。缺少出手锚点的预测读数在其可用时刻以“输入读数”说明。

“战术实验室”可以比较两个回合的空间、时序与指标。同屏相对进度只方便观看，不证明两个回合拥有相同战术阶段或严格逐帧同步。近防距离、传球段间距和防守几何都来自提供的轨迹；不以几何量替代官方模型输出。

实验室只在两边读数可用、语义、单位、定义、声明范围、来源类型和内核兼容口径一致时展示直接比较。即使读数没有排序尺度或方向，也单独检查其声明范围与示意／测量分界；不同范围、已声明与未声明范围混用、或示意与来源记录混用会显示不可直接比较。未知语义的指标只能单独查看，不能比较。Gravity 必须有明确单位和非空定义；有有效范围且声明为越大越强时才生成归一化排名分量，否则保留原值，不参与该分量排名。直接比较还要求声明方向一致。只有这些依据一致的原始读数才可并排比较，这不意味着它已具备排序分数或来源认证。项目切换按钮在窄屏仍可使用。

指标解释遵守以下边界：

| 指标或派生量 | 如何使用 |
| --- | --- |
| 投篮难度 / xFG | 先核对字段定义。概率不等于个人命中率，也不等于实际结果；`xFG × 出手分值` 仅是该次出手的输入期望得分，不是完整 EPV。 |
| Gravity | 保留提供者输出、单位与版本；没有则未知。最近防守者距离不能命名为官方引力。 |
| Leverage | 保留口径。回合胜率机会差、累计关键贡献与其他评分不能靠范围相似合并。 |
| 空间窗 | 显示身份、阈值、样本和缺口；几何开放不证明可传、无人干扰或因果收益。 |
| 回看排序 | 显示各分量与覆盖率；缺失项保留缺失，不用零假装“低价值”。 |

问答默认由本地证据引擎检索已有数据，执行可见步骤并返回引用。它能说清系统知道什么与不知道什么，不自动解析任意 NBA 转播的人物身份或战术名称。

## 7. 故事导演：解说、标注与片单

从观赛台把回合“加入片单”。在“故事导演”调整片段顺序和入出点，点击“保存片段入出点”。出点必须大于入点，且位于该回合范围内。

逐句解说有画面时间锚点和证据 ID。可编辑每句文案，保存后标为人工修改并撤销复核。引用证据 ID 仅表明关联；人工内容仍需检查是否真的受到该证据支持。“试听当前解说”使用浏览器语音，只用于试听，不意味着导出的 WebM 有音轨。

在暂停画面选箭头、区域或文字标签，依次点击起点与终点。人工标注自当前时刻显示 3 秒，记录人工来源；它不会改变镜头的自动追踪状态。可清除本回合人工标注。

连续预览按保存后的片单播放。项目修订与播放控制变更会终止过时预览；有解码帧回调的浏览器优先使用实际 `mediaTime`，否则会标记近似时钟路径。预览不是编码成片时长的证据。

发布前，按当前解说模式和图层逐回合核对：原视频时刻、箭头与色块位置、证据、人工文案、来源声明。勾选“我已核对当前回合的时间、标注、解说与来源”。所有片段都满足当前复核签名后才能生成。

改文案、标注、时间或视频会撤销相关复核；切换解说视角或图层后，原复核签名不能批准新成片。复核是操作者确认，不是软件认证数据真伪。

## 8. 成片与资料交付

### 浏览器录制

浏览器把选片、叠加和字幕录制为真实 WebM：1280 × 720，单次最多 180 秒、片单最多 2,000 段。它不保留原片音轨。支持性取决于实际浏览器编码能力；保持页面前台，并等待完成再关闭或切换项目。录制期间编辑控件停用，取消入口保留。

完成后下载成片及录制校验 JSON。校验应区分计划片长、实际录制时长、帧数和时钟路径。静态 Pages 的 Blob 只在当前页面存活；刷新、离开或切项目可能使下载链接失效。

### 本机中文 MP4

本机工具满足条件时可以勾选配音。系统用 Tingting 朗读已编排的字幕窗，合成 H.264 / AAC MP4，仍不保留原音。过密文案不能在时间窗内合理读完时明确报错，避免无提示截断尾词。语音与画面窗的对齐包含小幅时长适配，不能由此声称逐帧语音精确同步。

有声或无声成片可经本机受控接口保存。服务核对媒体容器、编码、实际时长与 SHA-256 后生成本机下载地址；保存不认证输入分析和视频来源。上限：单次媒体 64 MiB、本机库最多 20 个成片、总计 256 MiB。达到上限不会自动删旧片。

保存失败时页面明确提示“本机保存未完成”，保留当前成片供立即下载；不要把这个页面链接当作持久成片库记录。已保存库位于 `workspace/arena_artifacts/`，停服务后可连同工作区整体备份。当前没有库内删除界面。

### 其他交付

项目可下载可打印 HTML、WebVTT 和分镜 JSON；WebVTT 按裁剪、排序后的成片时间重映射，不沿用原视频绝对秒数。分镜包含证据、解说与片单定义，项目备份用于恢复编辑，二者都不包含原视频。

| 文句 / 来源 | 5 个证据关联字幕窗，人工精简；合成数据。 |
| 该文件的边界 | 离线渲染文件；来源未经认证、模型未实调、语音逐帧精确对齐未认证。 |

[离线校验](arena-assets/export-validation.json) 保存逐句时间、语音长度、调速和来源。PPT 采用真实产品截图和浏览器真实成片截帧；[PPT 校验](arena-assets/deck-validation.json) 单独记录 18 页、3 个可编辑原生图表、8 个原生表格、文件指纹与视觉检查，不把演示图表当作真实球队表现。

可复现离线链路：

```sh
npm install
node tools/export_arena.mjs --output workspace/arena-silent.mp4
python3 tools/narrate_arena.py --video workspace/arena-silent.mp4 --report workspace/arena-silent.mp4.json --output workspace/arena-voiced.mp4
```

自有素材可给导出器传入 `--project`、`--video`；需已复核项目。离线链路重采样为 25 fps，裁剪点须符合其帧栅格限制。对可变帧率原片，应独立逐帧核对；离线共享内核与浏览器录像的验收记录分别保存。

## 10. 可选模型 Agent 与信任边界

在本机入口进入“素材与校准 → Agent 连接与执行 → 设置”。默认本地证据引擎完全可用，它不是 LLM。

Ollama 只连接固定 `127.0.0.1:11434`，需用户已有支持工具调用的模型；服务端可通过 `COURTLENS_OLLAMA_MODEL` 指定。Bedrock 可通过 `COURTLENS_BEDROCK_MODEL` 指定模型，使用已配置 AWS 账户和模型权限，地区读取 `AWS_REGION`。网页不提供密钥输入、不安装模型、不在未连接时声称成功。

启用 AWS 时需确认将问题和当前比赛的结构化证据发送至该账户；原视频不发送，调用可能产生账户费用。文本和数字属于输入数据，不得作为改变工具或规则的指令。

模型通过注册工具 `search_plays`、`read_evidence`、`publish_story` 选择已有声明。发布前须在此前一轮读到相应证据；不存在、跨回合、未来时刻或未读引用会被拒绝。答案文句由本地字段编译，自由生成的长文不能直接当作已验证解说发布。无法支持问题时返回信息不足。

预算为：100,000 字节输入、1,200 字符问题、4 轮、8 条声明、12 次工具调用、45 秒截止。服务端验证输入结构、有限数值、单位、归属和时序；它没有重新测量视频、重算浏览器全部轨迹或认证 NBA 来源。模拟协议通过不等于 Bedrock / Ollama 真机调用通过；当前两种真实模型调用均未验收。

## 11. 项目保存、历史与备份

Arena 在当前浏览器保存独立项目、视频 Blob 和修订历史。修改后形成新 revision；恢复历史也形成新 revision 并撤销复核。跨标签页修改版本不一致时拒绝覆盖，先备份当前项目，再载入最新内容比对。

线上与本机、localhost 与 127.0.0.1、不同端口和不同浏览器属于不同存储来源。项目不跨这些地址自动出现。浏览器配额由浏览器决定；隐私模式、清除网站数据或系统清理可能使内容丢失。归档不是外部备份。

完整可恢复材料至少包括：Arena 项目 JSON、对应原视频、来源字典／许可、必要成片和校验。重新导入备份后仍需绑定相同原视频并复核。原 SQLite 工作区另须停服务后复制整个目录；不要只复制数据库或一段成片。

## 13. 常见问题

| 现象 | 处理 |
| --- | --- |
| 项目在另一个入口消失 | 回到原浏览器、原地址和端口；跨来源需要 JSON 备份与原视频重新接入。 |
| 视频已登记却不能播放 | 核对实际编码；容器扩展名不保证浏览器能解码。使用本机支持的编码重新准备原片后绑定并复核。 |
| 球场轨迹没有画回视频 | 检查单位、坐标区域、当前时刻镜头段、标定范围和连续轨迹；不要手工把无标定状态改成成功。 |
| 指标显示未提供 | 核对字段映射、定义与可用时间；空值不应强填零。 |
| 时间全部偏移 | 检查是否重复同步、用比赛钟代替视频秒数、原片是否剪切；从备份或历史恢复后重新核对锚点。 |
| 提示先复核所有片段 | 核对当前视角和图层，逐回合复核；旧签名不批准新模式。 |
| 中文配音按钮不可用 | 从本机入口打开，核对 macOS Tingting、FFmpeg / FFprobe 是否已安装并可用，再重启。 |
| 配音文句过密 | 精简人工文案或调整合法字幕窗后重新复核；不应静默截断词尾。 |
| 本机保存达到上限 | 先下载并备份；停服务后整理成片库。系统不自动删除旧交付。 |
| 模型未连接、超时或非法引用 | 核对已配置模型与权限；查看真实执行记录。可以明确切回本地证据引擎，不把切换描述成原模型成功。 |

## 14. 正式比赛接入与提交

以 [官方赛题页](https://builderx.csdn.net/bcast-code#challenge) 与赛方最终文件为准。2026-09-28 13:43 实际获取的官网全文仍写明“完整赛题、数据说明、提交规范与评审细则即将更新”。当前已实现对应链路；正式素材到场后依次核对：

1. 视频版本、使用许可、起止、帧率、剪切与镜头段；保留文件指纹。
2. Shot Difficulty / Gravity / Leverage 的实际字段、单位、定义版本、可用时间、缺失值及模型口径。
3. 球员 ID、球队身份、球场坐标、单位、采样率、镜头坐标及视频时间映射。
4. 从明确、易核对的关键回合起步，检查叠加与解说，再处理更复杂回合。
5. 按真实素材更新产品演示、分析统计和验收；分别验证几何、时间、字幕与模型调用，不复用合成数据的成绩声明。
6. 核对现场提交格式、时限、代码复用范围、演示视频规格和团队材料，再冻结仓库与交付指纹。

官方素材是下一轮验收输入，不是已经完成的数据证据。训练科技的使用也不能单独证明球队冠军因果，研究依据见 [科技研究与产品边界](Arena-科技研究与边界.md)。
