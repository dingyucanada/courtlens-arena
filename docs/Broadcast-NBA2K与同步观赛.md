# NBA 2K 参考与同步观赛决策

2026-09-30。依据用户提供的官网赛题正文、赛前培训摘要和官方游戏资料。赛题官网当前抓取失败，因此此处不把未读到的最新页面内容当新增硬性要求。

## 从游戏借鉴什么

[2K 官方 NBA 2K26 新闻](https://newsroom-uk.2k.com/news/latest-presentation-enhancements-bring-lifelike-atmosphere-and-authenticity-to-nbar-2k26)明确介绍了实况与分析解说、比赛末段随紧张程度变化的语气，以及对应重要时刻的呈现。[2K 开发团队对 NBA 2K21 的介绍](https://newsroom.2k.com/news/get-a-closer-look-at-nba-2k21-gameplay-on-next-gen-with-visual-concepts-developers)区分实况、分析、场边三种职责。

这些公开材料没有披露完整的解说事件调度算法。本项目借鉴的是可见产品原则，而非声称复现2K内部实现：

- 动作优先。短实况先报动作，解释在空档补上，不能每秒都塞术语。
- 按比赛上下文选择表达强度。没有比分、节次及权威关键度依据时，不编造“绝杀”“改变胜率”等标签。
- 声画由统一时钟驱动。暂停、回拖、跳转、倍速都会改变当前呈现内容。
- 回放与细节解释可供主动查看；普通观众默认只看一条主信息。

技术差别：游戏引擎能够提供自己的球员、球权、位置、事件状态；本项目从普通转播画面推断这些状态，会有遮挡、切镜、错号及处理延迟。因此不能把游戏体验当成真实视频识别准确率或延迟保证。

## 比赛取舍

| 能力 | 本版优先级 | 判断依据 |
|---|---|---|
| 视频、解说、箭头与官方数据时间一致 | P0 | 赛题明确要求对应画面，是主体验 |
| 导入视频后完成分析、复核、合成，按源PTS播放 | P0 | 能在官方短片到手后实际交付成片，处理与播放解耦 |
| 暂停、逐帧、原片同刻对照、当前证据 | P0 | 便于观众理解、评委核查和修正错误 |
| 当前动作与有效指标随进度出现、过期消失 | P0 | 不把上一动作或未来指标留在新画面上 |
| 基于已见防守变化的条件式提醒 | P1 | 可加分，但只能在证据充分时启用，未知就不显示 |
| 从实时流边收边看、数秒延迟生成语音 | P2 研究 | 赛题已知输入是短视频，没有硬性直播延迟指标；先测再承诺 |
| 胜负预警、未校准战术概率、伤病风险警报 | 不进入本版 | 缺数据/标注/评估，容易误导并偏离解说任务 |

“动态”不意味着数字一直跳动。xFG通常属于出手事件，GRAV/LVG的粒度、单位及有效时间以Portal字典为准；不在记录之间擅自插值。无官方数据的测试片只讲可见事实。

## 双时钟设计

**处理时间**决定何时准备好候选、语音及成片；**视频源PTS**决定某个事实何时可对观众说。预先生成不允许提前剧透：解说节点仍须晚于证据可用时间；结果需独立结果观察，预测不可读取未来帧或未来PBP。

当前MP4里的语音、字幕和箭头已经按同一时间轴合成，播放时不发模型请求。浏览器侧的当前章节、依据和指标卡同样从源PTS计算。回拖会重新计算状态，结束时清空；不会通过累积“上一个事件”保留过期标签。切换原片与成片须保留sourceRange偏移，不能从不同比赛时刻比较。

真实直播研究另测“输入帧到识别”“识别到文本”“文本到首音频”“播放缓冲”各段P50/P95，并以盲标动作与人物准确性约束。尚未测出这些端到端延迟，不能把本机RF-DETR单次240帧34.9秒误报为直播解说速度。
