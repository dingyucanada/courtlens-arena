# CourtLens Broadcast · 参赛产品蓝图

版本：2026-09-30。依据：用户提供的 CSDN 赛前培训纪要与[公开赛题页](https://builderx.csdn.net/bcast-code#challenge)。公开页仍写明“完整赛题、数据说明、提交规范与评审细则即将更新”；Portal 原始规则、官方视频、指标字典、AWS 账号仍未取得。本文件把设计目标、已实现能力和待验门槛分开；[设计裁决](Broadcast-设计裁决.md)、[AWS 部署](Broadcast-AWS部署.md)与代码合同仍是工程细则。

## 作品主张与评委的 90 秒体验

**让一段进攻从“发生了什么”变成“为什么这个选择改变了比赛”。** 输入是普通直播画面和赛方记录；输出是真实 MP4/VTT 和可交互观赛页，而不是单独的数据看板。评委打开 CloudFront 链接后，先看到画面中的关键动作，再看到一条随源片时钟出现的解释；暂停或重看时，信息同步回退；点“依据”能看见那句话来自哪一帧、哪条审核观察、哪条官方记录。若没有可确认的数据，画面说可见事实，不造 xFG/Gravity/Leverage 数字。

90 秒展示路线：打开一段已生成的真实源片成片 → 看前 1 个关键选择及短时箭头 → 点“重看这一刻”核对动作 → 打开依据抽屉核对时间与来源 → 展示制作台从原片到审核、出片的实际任务。赛方素材到手后替换授权影片和官方指标，不沿用合成演练的故事。

## 竞品学习与自己的取舍

| 一手产品/资料 | 学到的可复用原则 | CourtLens 的落实 |
|---|---|---|

| [Genius Sports / Second Spectrum NBA 增强转播](https://www.geniussports.com/newsroom/nba-and-genius-sports-second-spectrum-expand-partnership-to-deepen-nba-league-pass-innovations-with-enhanced-basketball-analytics-and-develop-new-next-gen-platform/) | 跟踪图层服务于转播，而不是替代比赛 | 主画面始终是比赛视频；默认每个节点最多一个主要数字、一条短时箭头、一句因果谨慎的解说。 |
| [Prime Vision 增强直播](https://www.aboutamazon.com/news/aws/prime-video-thursday-night-football-next-gen-stats-ai-features) | 观众可自行选择增强视角、重看关键点和深入查看数据 | 成片/原片同源时刻切换、章节回跳、重看、随时间变化的信号席与证据抽屉。 |

三个候选机制的比较见[架构设计](Broadcast-架构设计.md)第 3 节；选择“整段语义提议 + 关键窗取证 + 官方事件绑定 + 人工审核”。密集逐帧追踪是增强项，不能阻断两小时考片窗口。赛题不是战术名称分类赛；在只有普通转播与两段训练片时，先证明“谁何时做了什么”，再谨慎解释为什么。球队战术知识库只作可查参考，不替代本回合证据。

## 真实系统的五层结构

```text
授权视频 + 来源声明 + SHA / PTS + 赛方深度数据 / 字典
  → Intake：探测、存储、切镜/时间基准、帧取证
  → Perception：多模态事件候选；可选检测/号码/OCR/球场投影
  → Grounding：源片帧、当场名单、官方事件 ID、时钟和指标作用域逐项核对
  → Editorial Agent：选择最多三个关键选择，写可核验、可撤回的解说候选
  → Human Gate + Deterministic Renderer：审核当前修订 → MP4/VTT/manifest → 观赛页
```

不把大语言模型当数据库或渲染器。模型不得补造坐标、球员身份、得分结果和三项深度数字。视觉框、跟踪 ID、球衣号码、球队、当场名单和姓名是连续的不同确定性层级；任一层不可靠时使用“持球人/弱侧队友”等画面可核对称谓。时间基准用源片 PTS，不把比赛钟当连续 48 秒轴。切镜后轨迹失效；指标的展示时间取官方记录可用时刻，不能提前泄露。所有人工编辑使旧审核失效；任务绑定输入版本，失败或取消不覆盖历史成片。

### 五个用户界面与状态

1. **素材厅（未入库/已入库）**：真实上传、素材权利、来源、时长、SHA；不显示虚假的“AI 已分析”。
2. **取证台（排队/提议/审核）**：大视频 + 源片时间轴 + 可跳回的观察卡；支持对模型候选接受、拒绝、身份留空、局部补帧。无模型时明确人工辅助路径。
3. **解说台（草稿/待修/已审）**：最多三个“铺垫—关键选择—结果”节点，时间窗、语句、一个数字与一个几何标注；可预览有效窗，显示缺失来源与不可用原因。
4. **出片台（运行/验证/发布/失败）**：先检查授权、审核 hash、指标绑定、字幕和音频时长；确定性编码成真正 MP4/VTT；发布不可变清单与下载链接。失败保留旧版本。
5. **观赛剧场（播放/暂停/重看/查证）**：视频占主导，信号席由源 PTS 驱动。章节卡只露标题和时间，未来数字到达前不剧透。原片可用时切换版本保持同源时刻；证据抽屉把解说还原为画面观察和已确认数据映射。

本轮已经把本地 `/broadcast/` 错误进入静态 Pages 展示页的路由改回真实制作台，并在观赛剧场加入同步信号席、重看及随时刻变化的证据入口。公开 GitHub Pages 仍是无后端的合成演练展示，**不是已部署 CloudFront 的比赛系统**。

## 视觉语言与信息规则

使用 NBA 海军蓝底、球场蓝、关键红；红色仅标关键选择/需要注意的变化，蓝色标定位、数据层和可交互控件。视频画幅最优先，侧栏是“这一刻的答案”，不能盖住球和持球人的动作。球员标签简短、有碰撞避让；动线最长只显示经确认的 1–3 秒。一个节点只给一个主数字，必要时加一个辅助定性短语；数据解释进入证据抽屉。桌面为 16:9 视频与窄信号席并列，手机为视频在前、信号席在后，不横向溢出。语音与字幕逐句对齐；配音供应商是可替换适配器，未确认 MiniMax/StepFun 为赛事指定供应商。

## 赛制映射与硬门槛

| 来自用户培训纪要的要求 | 对应交付/检查 | 当前状态 |
|---|---|---|
| 视频理解 + 可视化 + 解说成片 | 源片上传 → 观察 → 故事 → 真 MP4/VTT；两段训练、考试片逐一重跑 | 本地链路具备；赛方片和逐帧准确性待验 |
| 官方 xFG / Gravity / Leverage | 原字典导入、事件 ID 与源 PTS 绑定、失配拒绝、可用时刻显示 | 合同与测试具备；赛事真实字段待验 |
| GitHub 私有仓库并绑定 Portal | 比赛前改私有，再在 Portal 绑定并检查读取 | 目前仓库应用户要求临时公开；Portal 未开放 |
| CloudFront URL | CDK 部署后浏览器访问、视频 Range、API、登录、缓存与手机检查 | 账号未发放，未通过实云验收 |
| CDK 一个工程部署 | `infra/` 构建与 synth、部署输出 URL | 本地 synth/合同可测；实云待验 |
| AWS 指定 Agent 服务与地区 | 以 Portal/sample 确认精确服务和区域；Agent 运行记录可追踪 | 候选 AgentCore，赛事口径待核 |
| 20:00 硬截止 | 18:00 考片后立刻跑冻结流程，19:30 前完成可用版 URL 并核对仓库推送，留回滚时间 | 比赛当日执行 |

机器 35、人工 55、问答 4、投篮 6 是用户提供培训的总分拆分。工程聚焦机器资格与人工“准确、好看、可用”的交叉项；现场 10 分需参赛队员完成。评分细则及服务多样性不等于保证得分。当前最有价值的非 AWS 工作是：真实陌生片盲测、减少错认与幻觉、打磨 90 秒演示、真实浏览器与视频播放验收。盲测方法见[评测协议](Broadcast-盲测评测协议.md)；没有独立人工真值时不报模型准确率。

## 赛方资源到手后的最短闭环

先锁定比赛区域、指定 Agent 服务、模型 ID 和数据 schema，再用一段训练片验证源 PTS→官方事件→指标单位；第二段做留一片盲测。AWS 账户开通后 CDK 实际部署，打开 CloudFront 链接完成登录、上传、成片、下载、手机与缓存验证。考片当天只允许换素材、核对事件与精修文案/窗口，不在最后两小时安装新权重或改系统骨架。最终仓库改私有并完成 Portal 绑定，CloudFront URL 直接提交。
