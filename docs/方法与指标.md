# 方法与指标口径

## 系统责任边界

CourtLens 接收已给定的事件、指标、轨迹和时间，也允许用户用 CSV 或人工编辑建立回合。系统执行数据校验、明确的编辑排序、证据绑定解读、视频时间同步、持久保存与导出。新建视频时产生的全视频回合只是编辑占位，并非系统从画面识别出的比赛事实。

当前实现不声称从任意电视转播中独立检测球员、识别人名、识别全部战术或复现 NBA 的专有统计模型。人工圈画、已有追踪、来源统计和解释推断须分别陈述，不能合称为自动视觉理解。

## 统计含义

- **xFG%：** 来源规定模型条件下的预期命中概率，0.62 显示为 62%。高 xFG 通常表示模型预测更容易命中；一次命中或未中不是模型校准的证明，也不能凭一球断言手感、心理或选择正确。若官方传入“difficulty”分数，先查方向、单位及模型条件，不能直接改名 xFG。
- **Gravity：** 保留来源定义和原值。相对于期望基准的防守压力，是专业引力指标的重要思想。没有来源时不自行计算；最近防守者距离只能作为独立几何量，不能冠名“官方引力”。
- **Leverage：** 当前标准字段限定为 0–1 的“回合胜率机会差”。它不是实际前后胜率变化，也不等于球员累计 Leverage Score。非合成 JSON 和非空 CSV 输入必须显式声明此口径。正式数据若提供其他版本，应修改适配器和分析逻辑，不能靠截断到 0–1 掩盖语义差异。
- **编辑排序：** 公开规则用于挑选适合解释的回合，不是官方综合能力分、获胜概率、模型准确率或统计显著性。缺失指标不作零填补；用户应能看到选择理由和数据不足。

指标的自然语言定义与机器语义声明一起保存。赛方正式字典优先于宣传页面里的简写；本项目不估计未输入的专有统计模型。具体研究来源见 [专业产品研究](专业产品研究.md)，接入枚举见 [数据接口与接入](数据接口与接入.md)。

## 证据等级与复核

**观测**是数据给定的数值、事件或带时间的位置；**推断**是在观测上提出的可能篮球解释，应保留条件和不确定性；**不可用**表示没有对应字段或可靠时间位置，不能补写。数据源自行声明 `official` 不等于系统独立验证了官方真实性；原始文件、字典和组织方校验值须另行核对。

人工标注记录“操作者在特定图像位置加了标记”，不是球员自动跟踪或因果证据。把文字标签写成“吸引协防”不会自动证明发生了协防，更不能单凭圈画断言谁导致得分或漏防。

网页新建、导入和后续修改会进入 `workflow.state=draft`。操作者核对时刻与来源后可保存为 `reviewed`；产品后台导出必须明确具备此声明。此状态是人工声明，不是第三方审核。纯分析接口兼容无 `workflow` 的旧 schema 1.0；但持久创建、保存或恢复时会将缺失状态补为草稿，旧输入也须先保存复核声明再导出。外部集成须在修改内容后撤销复核，不能把结构校验通过当作审核证据。

## 时间、结果与视频身份

唯一播放时钟是视频 `currentTime`，所有事件标准化为该视频的秒。CSV 的节钟列只是文字，适配器不会猜测映射。比赛钟会暂停、倒计时会在每节重置，不能简单与视频时间相减。`core/calibration.py` 提供多锚点包围范围内的分段映射，拒绝外推；回放、广告和暂停后重新检查分段。

回放中只有在明确提供 `result_time` 后才按该时间宣布结果。没有这一时刻时，已知结果可以出现在完整赛后摘要，但不提前进入同步字幕。`points` 表示投篮分值，不能因标为三分球就当作已得到三分。

同步播放要求 `video.sha256` 与视频字节对应，并核对真实尺寸和时长，时长容差 0.1 秒。未完成核验或失败时清空叠加与字幕、暂停证据跳转；独立的数据阅读不能解释成当前画面的事实。持久上传与 `tools/bind_media.py` 都不负责证明事件真实性、授权或空间校准。单视频最大 512 MiB；裁剪、转码、旋转或换源后须重新校准和绑定。

## 追踪图层与人工标注的不同条件

**追踪图层：** 每个镜头独立声明 `calibrated`，未校准或镜头区间外暂停显示相关空间信息。只在同一镜头已知采样间内插，不越切镜边界、不向样本区间外外推，也不为相邻帧缺失的球员造位置。没有轨迹时不会自动检测出位置。坐标为 0–1 图像位置，非 16:9 视频按实际比例显示。

**人工图层：** 必须显式声明 `origin=manual`、`frame_reviewed=true` 和非空 `author_note`。整段标注必须落在一个已声明镜头段内，经操作者独立核对，可以在原追踪未校准时显示；原 `camera_segments.calibrated` 仍保持原值。人工箭头、区域和文字是时间受限的静态图形，不跟随球员。相机移动时须缩短区间或拆段；页面前后 0.1 秒按钮只是按时间跳转，不保证逐编码帧精确定位。

四点单应性仅适用于同一平面及同一镜头，源为球场坐标、目标为图像归一化坐标，不能重建空中球的三维高度。至少另留两个未参与拟合的检查点报告重投影误差，不能用拟合点的低误差证明泛化准确。

## 保存、导出与可重复性

每次保存或恢复形成新的 SQLite 历史版本，过期 revision 被拒绝。后台导出冻结已保存数据、revision 和视频副本，使用相同的证据与字幕计划；用户之后编辑不会改变该任务。输出核验通过后才提供成片、字幕和分析文件下载，文件指纹可用于检查结果是否被更改。

网页导出默认是带画面叠加与字幕的无音轨 MP4；macOS `say` 可用时，可显式选择本地中文配音。语音只由已编译的字幕及时间生成，附带记录，并核对语音记录与字幕证据一致。选择配音后若语音失败、过密或取消，不开放无声中间视频。两种模式均不混入原始音轨；本地语音合成不等于云模型推理。

这些机制改善输入、过程与结果的可追溯性，不会自动提升统计模型质量、证据真实性或篮球解释准确率。可选云规划 CLI 尚未真实实调，当前网页使用本地证据逻辑。

## 评价计划与当前证据

合成演练可检验输入异常处理、数值转写、引用闭合、时间边界、版本与任务隔离、失败恢复、模式切换及导出行为。它无法证明真实 NBA 战术理解准确率、检测泛化、观众理解提升、商业付费意愿或官方指标模型性能。

正式素材验收应对演示全部重要句人工核对，使用预留锚点和独立检查点评估误差，并注入缺失指标、错位和切镜故障。在同一组回合上，以普通模板解说和专业人工圈画作为强基线，记录数字错误、错位、修改与重新导出的步骤和时间，不故意削弱替代方案。

若实际招募了观众，可做匿名随机顺序比较；没有受试记录就不报告理解提升或满意度。目前真实 NBA 赛题输入、真实云调用和 Windows 实机验证仍未完成。软件实测环境、最终测试计数与浏览器回归统一见 [最终验收报告](最终验收报告.md)，本文件不另造验收数字。
