# NBA 深度赛场可视化 Agent：专业产品与研究边界

调研日期：2026-09-22。本文为独立研究输入，不是已完成产品或赛题评分细则。所有列出的来源均实际打开；下载实测单列记录。比赛要求由主代理从赛事官网核实：火箭对独行侠历史视频及官方深度数据现场领取；围绕投篮难度、球员引力、关键度识别回合，在原视频叠加箭头、色块、球员标注并同步解说。正式字段、视频和评分权重尚未获得。

## 最值得采用的产品方向

建议定位为 **“能把官方深度数据变成可核验视频解释的篮球解说导演 Agent”**。它的差异化应是：找出一个值得解释的回合，用原视频展示证据，准确说清哪个指标支持哪句话，并输出可播放的带解说视频。

12 小时的核心链条是：**导入 → 时间对齐 → 挑选回合 → 生成有依据的解释和标注计划 → 渲染 → 回看检查 → 导出**。把开发投入放在数据与视频之间的可靠连接、叠加的阅读顺序、解说节奏和错误修正。不要把任务扩成自研 NBA 官方模型或从单机位恢复全场三维骨骼。

Smartshot 展会照片可迁移的是“自动采集后立刻给出可读反馈”“场地上的可视解释”“从一次动作回到改进动作”的交互闭环。仅凭照片不能核实其测量精度、摄像头方案、正式客户范围或算法能力，不能据此宣称已经复现鹰眼。

## 与赛题三项指标的直接对齐

AWS 的 NBA 合作页列出 Shot Difficulty、Defensive Pressure、Gravity、Leverage；这与赛题高度匹配，但**不能由此断言主办方字段一定采用同一版本或量纲**。[S01]

| 指标 | 已核实的专业含义 | 12 小时原型的正确职责 | 应拒绝的替代说法 |
|---|---|---|---|
| 投篮难度 / xFG% | 以投篮情境估计命中可能性；官方专门释义强调与球员身份无关。[S02][S03] | 读取赛方 xFG 字段及版本；在出手前后显示该值；用实际可见的防守距离、姿态或赛方解释字段辅助说明。 | 用三分球占比、投篮距离、得分或球星名气直接冒充官方 xFG；把低 xFG 写成“选择错误”。 |
| 球员引力 / Gravity | 关注球员额外吸引的防守注意；需要实际与预期压力的比较。[S04][S16] | 有赛方结果则展示其随时间变化；画线和色块只锚定已知位置。解释“谁吸引注意、哪片空间出现”时附视频证据。 | 最近防守者距离、周围人数、普通热力图直接改名为 Gravity；将高压力一概视为好防守。[S05] |
| 关键度 / Leverage | 实际与反事实结果的胜率差，并通过上下文分配贡献。[S06] | 用赛方关键度选 Top 回合，说明为什么该回合重要；分别显示回合影响和球员归因。 | 用比赛前后胜率差替代反事实差；只取第四节最后两分钟；把全回合影响都归给得分者。 |

定义冲突需显式处理：NBA xFG 专文与 AWS Leverage 工程博文对是否包含球员能力的简述并不一致；对“官方 xFG”的解释以正式赛方字典为准，不自行补充未给特征。[S03][S06] 原型中的字段应带 `provider / metric_name / version / unit / scope / timestamp / source_row_id`；此为研究建议，不是假定赛方已有这些列。

## 十二个可迁移机制

下表中“已有能力”指产品帮助文档、工程文章或官方案例可核实的内容，并不代表我们独立测过其精度。营销稿中的“首个”“最准确”“广播级”均不作性能证据。

| # | 机制与参考 | 已有能力 / 成熟度 | 数据前提 | 12 小时可实现部分 | 不应声称 |
|---|---|---|---|---|---|
| 1 | **一条解释直达一段证据**：Synergy、Hudl | Synergy 投篮点可打开关联片段；Hudl 统计报告链接视频，是成熟交互而非研究想象。[S09][S10] | 事件 ID、视频起止时间；投篮坐标仅用于投篮点。 | 每张“为什么重要”卡绑定 1–3 个时间片段，点击同步跳转，选中球员/指标同步高亮。 | 有了统计就已识别完整战术；视频存在标记等于视频可下载或可再分发。 |
| 2 | **在出手时展示难度，落球后展示结果**：NBA Inside the Game | 官方产品将出手条件与结果分开解释。[S02] | 赛方 xFG、shot event、release time，必要时有解释字段。 | 两阶段叠加；命中/未中后也保留“出手前预期”，避免结果倒推。 | 用最终是否命中反向生成一个看似准确的难度分数。 |
| 3 | **让无球价值可见**：Gravity | NBA/AWS 已有正式指标；AWS 同类平台文章说明实际/期望压力思路。[S04][S16] | 同一时间基准的球员/球位置、赛方 Gravity；最好有 DPS/xDPS。 | 一次只突出 1 名牵制者、1 次防守偏移、1 片受益空间；附来源时刻。 | 普通广播视角下看不见的球员也被准确恢复；把合成防守移动标成真实。 |
| 4 | **以影响选片，不以得分选片**：Leverage | AWS 工程案例覆盖反事实胜率、回合归因与事件关联。[S06] | 赛方关键度，事件类型、球员归因、比分和节次。 | 同时挑一个得分回合和一个篮板/失误/防守回合；排序理由可展开。 | 系统掌握未提供的真实胜率模型；关键度等于“必胜贡献”。 |
| 5 | **解说先输出结构化证据计划**：Play Finder 的可检索思路 | AWS 发布了按回合检索的产品方向，但发布稿中的未来球迷功能不能一概当成当时已开放。[S02] | 可靠事件索引、官方指标、必要的视频观察。 | Agent 先给 `claim → evidence → interval → overlay → narration`；校验通过再渲染，支持一句指令改写。 | “自由聊天”本身就是深度分析；模型给出的因果故事自动视为事实。 |
| 6 | **严格区分标签来源**：Synergy 人工上下文 | 官方 API FAQ 说明深度回合上下文有人工标注，产品为赛后数据；普通事件 API 与 Synergy 不是一套数据。[S11] | 赛方标签/人工标签/模型推断的 provenance。 | 把“官方标签”“人工确认”“候选判断”分开保存；只选高把握的 2–3 类战术描述。 | 看到助攻就判定挡拆；一套通用多模态模型已达到专业球探标注水平。 |
| 7 | **原视频增强视图**：Second Spectrum、GeniusIQ | NBA League Pass 增强合作有官方公告；2025 FIBA U19 有带速度、投篮图等叠加的实际案例。[S07][S08] | 已标定追踪数据、时钟同步、可显示视频。 | 球员光圈/箭头/空间色块三类基础语言，逐层出现；字幕避开比分牌、篮球和关键手部。 | 任意电视转播上稳定实时 AR；无跟踪和标定也有精确物理空间。 |
| 8 | **自动导播的“少而有因”**：Sportradar Automated Video | 产品页描述自动拍摄、制作、直播，且给出法国 LNB 场馆部署案例。[S12] | 固定部署摄像头、控制拍摄链路、视频/事件同步。 | 已有比赛片段上的节奏编排：原速 → 关键短暂停留 → 局部标注 → 恢复原速；可人工撤销。 | 12 小时桌面演示已替代硬件采集、摄像机控制和职业导播体系。 |
| 9 | **捕获条件先行**：HomeCourt | 产品提供投篮追踪、回看；官方 FAQ 列出光照、篮网、球场线和单射手等有利条件。[S13][S14] | 清晰可见目标、有限拍摄条件。 | 导入时给出“可定位/需校准/证据不足”的状态；低质量时保留字幕和图表，停止漂移的球员标注。 | 单人训练条件下的识别能力可直接迁移到 NBA 多人遮挡、切镜、回放。 |
| 10 | **从一个结果回看整段创造过程**：EPV | POINTWISE 与后续论文用追踪数据估计回合最终预期得分，能分析终结之前的动作价值。[S17][S18] | 高频空间状态与训练模型；仅 PBP 不够。 | 借用叙事结构：创造优势 → 传递优势 → 完成终结。可展示已有赛方量值，不临时伪造 EPV。 | EPV 等于 xFG；普通事件列表足以精确计算每次无球跑动价值。 |
| 11 | **空间证据优先于主观防守归责**：防守空间研究、Hawk-Eye | 防守研究基于追踪与统计模型；NBA 与 Hawk-Eye 合作公告区分已部署追踪与未来自动判罚机会。[S15][S19] | 连续轨迹、匹配身份、坐标质量；精度需实测。 | 解说分层：“两人靠近持球者”是观察；“因此弱侧出现空间”是有证据的解释；“某人漏防”需更多证据。 | 只凭最近防守者就断言战术责任；把二维示意叫鹰眼级三维还原或裁判系统。 |
| 12 | **允许修正的回合时间轴**：PBPStats | 工具提供回合边界、场上阵容、部分事件顺序修正。[S20] | 官方事件、节次时钟、换人及控制权规则。 | 把自动识别的回合起止、暂停/切镜、字幕区间开放为可拖动项；保留修改前后的差异。 | 逐回合时钟天然等于视频时间；罚球、争球、进攻篮板均可用“换队”一条规则处理。 |

## 对 12 小时实现的优先级建议

以下为本研究的工程建议，不是赛事评分权重。

**必须跑通：** 导入一个授权比赛视频及对应数据；从三项指标中选定 3 个有差异的回合；原视频上展示可追溯叠加；同步简洁中文解说；导出最终可播放视频；每句重要判断都能回到数据行/视频时间。

**可靠性比额外模型更值钱：** 先验收片段边界和时间对齐，再评估讲得是否精彩。比赛时钟会暂停，转播会切回放和广告；不能对全场只做一个固定时间偏移。推荐分段锚点（节次、剩余时间、事件/可见比分）与逐段检查，不能定位时要求人工锚点，而不是静默错位。

**数据按三档工作：**

1. 有官方指标和视频位置：做完整增强解说。
2. 有指标但没有可信画面定位：做时间片段、字幕、边栏数值和明确的战术示意小窗；不画跟随真人的漂移箭头。
3. 只有合成练习数据：所有画面、导出视频及说明持续显示“合成校准样例”，指标值不冒充 NBA 官方结果。

**优先删掉：** 临时训练官方 xFG/Gravity/Leverage 替代模型、实时多摄像头采集、三维自由视角、自动裁判、无来源伤病/体能建议、多赛季球探平台。官方已有深度数据时，这些投入不会直接改善本题核心交付。

## 可验收的差异化样例

准备三个可重复播放的演示脚本：

1. **难球不一定是错球。** 展示出手条件与官方难度值，再显示结果；即使命中也不把结果当成决策正确的证明。
2. **没有触球，也可能创造机会。** 根据赛方引力指标挑回合，用原视频展示防守注意变化和受益区域。没有足够空间证据时，只报告指标，不补写虚构路线。
3. **最关键的一球可能不是得分。** 从关键度排序中选一个篮板/防守/失误回合，解说它与比赛情境的关系，明确回合分与球员归因的差别。

演练自定验收项：片段起止不截断解释动作；每个标注有真实锚点；所有数值与源行一致；字幕不覆盖关键目标；语音不超过片段时长；回放中的数值不提前泄露结果；低置信判断能删改；重新导出仍复现同一结论。除非已经实测，不写“95% 准确率”“零延迟”“鹰眼级”。
